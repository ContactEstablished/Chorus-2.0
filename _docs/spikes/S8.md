# S8 — Per-user installer

**Verdict: pass, with one collision to settle before anyone installs 2.0 normally.** The installer
needs no admin rights, installs beside Chorus 1 without touching it, and uninstalls leaving 2.0's
data. But with the product name "Chorus" it would create `Chorus.lnk` in the Start menu and on the
desktop, **the exact paths of Chorus 1's shortcuts**, overwriting them. The test therefore installed
with `/NS` (no shortcuts). OPEN-QUESTIONS Q20 asked Matthew how to name 2.0's shortcuts: "Chorus 2" (D51).

Tested 2026-10-18 with Tauri CLI 2.12.3's NSIS bundler (NSIS 3.13, `nsis_tauri_utils` 0.5.3),
`installMode: currentUser`, from a non-elevated shell, against Chorus 1 0.9.4 installed and running.

## Footprint (from the generated `installer.nsi` and a live install)

| | Chorus 1 (electron-builder) | Chorus 2.0 (Tauri NSIS) | Collides? |
|---|---|---|---|
| Install folder | `%LOCALAPPDATA%\Programs\Chorus\Chorus.exe` | `%LOCALAPPDATA%\Chorus\chorus.exe` | no |
| Start menu shortcut | `Programs\Chorus.lnk` | `Programs\Chorus.lnk` (or in a folder if `startMenuFolder` is set) | **yes** |
| Desktop shortcut | `Desktop\Chorus.lnk` | `Desktop\Chorus.lnk` (finish-page checkbox, and always in `/S` or `/P` installs) | **yes** |
| Uninstall entry (HKCU) | `Uninstall\85aec796-…` "Chorus 0.9.4" | `Uninstall\Chorus` "Chorus" | no (but two "Chorus" rows in Apps) |
| Other registry | — | `HKCU\Software\contactestablished\Chorus` (install path; kept on uninstall unless app data is deleted) | no |
| Data | `%APPDATA%\chorus-app`, `%APPDATA%\chorus` (dev) | `%APPDATA%\com.contactestablished.chorus2` and `%LOCALAPPDATA%\…` (WebView2) | no |
| "Is it running?" check | — | Restart Manager on the **full path** of 2.0's exe, so it can never match Chorus 1's `Chorus.exe` (LESSONS L21) | no |

## What was done, and how

1. Read-only snapshot of Chorus 1: a hash over its 407 installed files (path, size, mtime), both
   shortcuts (target and mtime), its uninstall entry, its data folder, and its 5 running processes
   (selected by executable path).
2. `Chorus_0.1.0_x64-setup.exe /S /NS` from a non-elevated shell: exit 0 in about 1 s, no UAC
   prompt, nothing written under HKLM. Installed `chorus.exe` and `uninstall.exe` into
   `%LOCALAPPDATA%\Chorus`; no shortcuts.
3. Snapshot again: every Chorus 1 item identical, its processes the same PIDs.
4. Launched the installed `chorus.exe`: release identifier `com.contactestablished.chorus2`, its own
   data folder, no dev harness. Stopped it by PID.
5. `uninstall.exe /S`: install folder and uninstall entry removed; Chorus 1 identical; 2.0's Roaming
   and Local data folders **still present**. The leftover `HKCU\Software\contactestablished\Chorus`
   key (the remembered install path) was removed by hand afterwards to leave the machine as found.

**WebView2:** the installer is in `downloadBootstrapper` mode: it checks for the evergreen runtime
and downloads Microsoft's bootstrapper only when it is missing. It was present (155) and the step was
skipped. Windows 11 ships the runtime and v1 is Windows-only (D21), so this mode is enough;
`embedBootstrapper` is the fallback if an offline-first install ever matters.

## Install path decision

`%LOCALAPPDATA%\<product name>` per user, Tauri's default (D39): no admin rights, and separate from
Chorus 1's `%LOCALAPPDATA%\Programs\Chorus`. Data follows the identifier, not the product name, so it
is unaffected by Q20's answer.

## What it means for the plan

Nothing in the plan changes, but **until Q20 is answered, install 2.0 only with `/NS`** (or not at
all) on a machine that has Chorus 1. P14 owns the remaining installer polish (code signing, update
channel, the uninstall data checkbox wording).
