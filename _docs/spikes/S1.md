# S1 — PTY host

**Verdict: pass**, with two findings for P1 (Close must spare browsers an agent opened; the Job Object
is assigned just after spawn, not atomically).

Tested 2026-10-18 on Windows 11 (build 26200), WebView2 155.0.4283.62, Tauri 2.12.4, portable-pty
0.9.0, `@xterm/xterm` 6.0.0 with `addon-webgl` 0.19.0 and `addon-fit` 0.11.0. Agents: Claude Code
2.1.300, codex-cli 0.162.1, opencode 1.18.34, grok 1.0.5.

## What was built (kept as real code)

- `src-tauri/src/sessions/`: ConPTY via portable-pty; one reader thread and one batching thread per
  session; output streamed over a `tauri::ipc::Channel` as **raw bytes** (`InvokeResponseBody::Raw`,
  typed as `Channel<ArrayBuffer>` in the generated bindings), so there is no JSON or base64 on the hot
  path. Commands: `pty_spawn`, `pty_write`, `pty_resize`, `pty_close`; event `pty-exited`. Inputs are
  bounded at the boundary (size 2–1000, writes ≤ 1 MiB, the session must exist).
- `src-tauri/src/sessions/job.rs`: one Job Object per session with `KILL_ON_JOB_CLOSE`.
- `src-tauri/src/agents/`: launches each CLI through its real install: `claude.exe` and `grok.exe`
  directly, the npm shims parsed to their target (`node …\codex.js`, `…\opencode.exe`), never
  `cmd.exe /c`. Auto-update off: `DISABLE_AUTOUPDATER=1`, `-c check_for_update_on_startup=false`,
  `OPENCODE_DISABLE_AUTOUPDATE=true`, `GROK_DISABLE_AUTOUPDATER=1` (see below).
- `chorus-core`: `env` (minimal child environment), `shim` (npm shim parser), `batch` (flush
  policy: 8 ms window or 256 KiB), all unit-tested.
- `src/components/TerminalView.vue`: xterm.js fed raw bytes (its UTF-8 decoder keeps state across
  chunks), WebGL renderer with a visible fallback to DOM on context loss.

The throwaway part is `src/spikes/PtySpike.vue` (dev builds only), driven from a DevTools Protocol
script with WebView2's `--remote-debugging-port`; P1's Raw view replaces it.

## What was measured, and how

All steps ran in the real dev app. Frame times were sampled with `requestAnimationFrame` from the
moment the command was sent until output had been quiet for 750 ms, plus a `longtask` observer.

| Test | Result |
|---|---|
| **10 MB burst** (`type` of a 10 MiB file with SGR colours, in `cmd.exe`) | 11.6 MB arrived through ConPTY in 586–592 messages over 4.9 s. Worst frame **4–9 ms**, p99 4 ms, **0 frames over 50 ms**, 0 long tasks (two runs). The tail rendered correctly. |
| UTF-8 | `✓ café è 日本 🎵` renders correctly once the shell is in code page 65001. Under cmd's default code page 437, `type` of a UTF-8 file shows mojibake; that is cmd, not the pipeline. |
| **Resize** | Shrinking the terminal element from 140×27 to 86×19 reached the PTY: `mode con` reported 86 columns, 19 lines. |
| **Ctrl+C** | `\x03` stopped a running `ping -t`; cmd printed `^C` and kept working. In Claude Code it showed "Press Ctrl-C again to exit". |
| **Launch through real installs** | All four started in the PTY with the minimal environment (nine names: `PATH`, `SystemRoot`, `TEMP`, `TMP`, `HOMEDRIVE`, `HOMEPATH`, `USERPROFILE`, `TERM`, `COLORTERM`, plus per-agent switches). Claude Code found its subscription, Codex its login, opencode ran on isolated `XDG_STATE_HOME`/`XDG_DATA_HOME`. Nothing needed adding to the allow-list. |
| **Close kills the tree** (process list by `Name` and `CreationDate` before and after, LESSONS L12; only processes descended from this session) | cmd with three background grandchildren (8 processes, 3 levels, one with its own console): all gone. Claude Code plus the plugin MCP server it started (3): gone. Codex (13: `codex.exe`, `git` fetches, `node_repl`): gone. opencode (1): gone. Grok (11, see below): gone. `pty_close` reports the job's process list, which matched the snapshot each time. |
| **Crash leaves no orphans** | With cmd and two grandchildren running, the dev `chorus.exe` was killed with `Stop-Process -Force` (selected by PID and executable path). All 5 session processes were gone 2 s later. |

## Findings

1. **A Job Object kills browsers that an agent opened.** Grok isn't signed in on this machine
   (`~/.grok/auth.json` is absent), so it started a browser sign-in. Brave wasn't running, so the new
   Brave instance (8 processes) became a child of `grok.exe` and was inside the job; Close killed it.
   The same will happen whenever an agent opens a URL (sign-in flows, "open in browser") and the
   browser wasn't already running. **For P1:** on Close, clear `KILL_ON_JOB_CLOSE`, terminate the job's
   processes except GUI processes with visible top-level windows that the agent launched, then close the
   job. A crash of Chorus still kills everything, which is acceptable.
2. **The child joins the job a moment after it starts.** portable-pty doesn't expose `CreateProcess`
   attributes, so the child is assigned right after spawn. A grandchild created in that window would
   escape. None did in these runs (every tree matched the job's list). Closing the gap needs
   `PROC_THREAD_ATTRIBUTE_JOB_LIST` at spawn, which means a small patch to portable-pty or our own
   ConPTY spawn. Recorded for P1; not a blocker.
3. **Codex's `-c` overrides force "embedded mode".** Codex 0.162.1 warns at startup: *"Running without
   the shared background server: command-line configuration overrides (-c, --enable, --disable, or
   --search) requires embedded mode."* Our update-check switch is a `-c`, so every Chorus-launched Codex
   runs without the shared server. S5 checks what that costs (for example `codex queue`).
4. **Grok's auto-update switch is undocumented.** The README documents `[cli] auto_update` in
   `~/.grok/config.toml`; the binary also contains `GROK_DISABLE_AUTOUPDATER` and `GROK_AUTO_UPDATE`.
   Chorus sets `GROK_DISABLE_AUTOUPDATER=1`; its effect is unverified until an update is available.
5. **Shell sessions need UTF-8.** The Shell adapter (P2) should start cmd in code page 65001.
6. **Process names collide with Chorus 1** (LESSONS L21): a `Name='chorus.exe'` query also returns
   Chorus 1's `Chorus.exe`. All tooling here selects by PID and executable path.

## What it means for the plan

The P1 design stands: portable-pty + one raw-bytes channel per attached view + an 8 ms batch is fast
enough that a 10 MB burst never drops a frame, and per-session Job Objects clean up real agent trees,
including on a crash. P1 adds the browser exemption on Close (finding 1) and should close the spawn
race (finding 2). PLAN P1 is updated to say so.
