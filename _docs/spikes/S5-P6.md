## Q19: measured versus advertised

Read the installed `codex --help`, `codex app-server --help` and its generated JSON schema.
The CLI advertises `app-server --listen`, WebSocket capability-token authentication with
`--ws-token-sha256`, TUI `--remote`, and `--remote-auth-token-env`. Generated protocol contains
`turn/plan/updated` with `threadId`, `turnId`, optional explanation and steps whose status is
`pending`, `inProgress` or `completed`. This is schema evidence, not a delivered plan.

Two bounded probes used scratch directories outside the repository:

1. A private stdio app-server accepted `initialize`/`initialized`, reported a ChatGPT subscription
   account, created an ephemeral read-only thread and completed one tiny turn. No shell commands,
   files, network tools or delegation were requested. It emitted turn/item/message notifications
   but **no plan update**, despite a request to make a tiny two-step plan. This is inconclusive for
   plan support, not proof that the channel is absent.
2. A private loopback WebSocket server used a freshly generated capability token. Only its SHA-256
   digest was in server argv; the token reached the TUI through its environment. A real TUI under
   ConPTY connected and showed Codex 0.163.0 and the scratch-folder trust dialog. The probe ended
   there without submitting another model prompt or changing folder trust. It used no shared daemon.

The first ConPTY attempt encountered the CLI's `TERM=dumb` confirmation. Repeating with the app's
`TERM=xterm-256color`/`COLORTERM=truecolor` reached the remote TUI. Probe processes were bounded and
ended; unrelated Chorus and agent processes were left alone.

[Official app-server documentation](https://learn.chatgpt.com/docs/app-server) describes the client
protocol and version-specific schema generation. Installed help and runtime results above take
precedence over assumptions about older flags. No new production transport dependency was added.

**Q19 remains open.** Before enabling a bridge: observe real plan updates; attach the Raw TUI and
Chorus controller to the same thread; verify plan, approval and question events, actual replies,
reconnect/cancellation/expiry and shutdown; establish an authenticated transport using the approved
dependency set. Until then, the UI explicitly says Codex plan updates are not connected. An
app-server launch without a real Raw TUI is not an acceptable replacement.

The shared delivery implementation is in `sessions/delivery.rs`, not a competing composer-only path.

  trusting the empty scratch directory, a tiny Raw bootstrap prompt completed and established Ready.

  changed from `written` to `observed`; retrying the same request returned that receipt without

Automated checks cover persist-before-write, separate text/Enter writes, multiline bracketed paste,
control stripping, byte bounds, partial-write uncertainty, durable retry receipts, transaction
rollback, same-run/time-limited echo consumption, scrubbing, stale run IDs, locking and refusing
unsupported question/approval actions. The slice passes 449 Rust tests, 19 frontend tests,
TypeScript, Clippy and the secret scan. Bindings were regenerated with `npm run bindings`.
