# S5 — Agent channels

**Verdict: pass for Claude Code, Codex and opencode, with changed details; Grok changed approach
(structured channels exist but could not be exercised: Grok is not signed in on this machine).**

Tested 2026-10-18 in the real dev app (agents in Chorus's PTY, minimal environment, Job Object), with
a throwaway loopback listener and harness in `_verify/`. Versions: Claude Code 2.1.300, codex-cli
0.162.1, opencode 1.18.34, Grok 1.0.62 (it updated itself from 1.0.5 during S1, see Findings). Turns
were few and tiny: Claude Code and Codex on subscription, opencode on its free, keyless "Big Pickle"
model with isolated state, Grok none. Docs were read from each CLI's own `--help`, bundled docs and
official pages; facts that came from docs alone are marked *(docs)*.

## What was measured, and how

### Claude Code
- Settings file in 2.0's app data with an HTTP hook per event:
  `{"type":"http","url":"http://127.0.0.1:<port>/hook/<session>","headers":{"Authorization":"Bearer $CHORUS_HOOK_TOKEN"},"allowedEnvVars":["CHORUS_HOOK_TOKEN"]}`.
  The token was injected through the S4 vault path as an environment variable. It was **not** in the
  settings file, argv, the URL or Claude's `--debug-file` log; an unauthenticated POST got 401.
- `SessionStart` is skipped: *"HTTP hooks are not supported for SessionStart"* (debug log). Every
  other event used arrived: `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`,
  `Notification`, `Stop`, `SubagentStop`, `TaskCreated`, `TaskCompleted`.
- **Approval from Chorus works and races the TUI.** Claude draws its own dialog ~0.3 s after the
  `PermissionRequest` hook starts, while the hook is still pending. A hook answer 12 s later dismissed
  the dialog ("Allowed by PermissionRequest hook") and the command ran. A hook **deny** with a message
  reached the model, which carried on and explained the refusal. A hook that never answered timed out
  (30 s here) and left Claude's dialog up; pressing Enter in the terminal approved it.
- **Question answered by Chorus**: `AskUserQuestion` arrived at `PreToolUse`; returning
  `permissionDecision: "allow"` with `updatedInput.answers = {question: "b.txt"}` made Claude write
  `b.txt` ("User answered Claude's questions: → b.txt").
- **Queueing**: a second prompt typed mid-turn was queued by the TUI ("Press up to edit queued
  messages") and ran after the first. Note: its `UserPromptSubmit` fired **at queue time, before the
  first turn's `Stop`**.
- **Interrupts**: choosing "No" in Claude's own dialog interrupts the turn ("Interrupted · What should
  Claude do instead?") and **no `Stop` fires**.
- `SubagentStop` follows each `Stop` by ~2 s; its `last_assistant_message` was Claude's own suggested
  next prompt ("mark beta completed").
- Transcript record types seen: `user`, `assistant` (text, thinking, `tool_use`), `system`,
  `attachment`, `queue-operation`, `last-prompt`, `ai-title`, `file-history-*`, `permission-mode`,
  `api-request*`. Tool names: `AskUserQuestion`, `Write`, `PowerShell` (the shell tool on Windows is
  **PowerShell**, not Bash), `ToolSearch`, `TaskCreate`, `TaskUpdate`.

### Codex
- First attempts: every hook failed ("hook exited with code 1") inside Chorus but worked from a full
  environment. Bisecting 15 standard variables found **`PATHEXT`**; it is now in the allow-list (and
  `SystemDrive`, for a Claude Code finding below).
- With it: `SessionStart`, `UserPromptSubmit`, `PermissionRequest`, `PostToolUse`, `Stop` all arrived.
  In a read-only sandbox, a file write raised `PermissionRequest` (`tool_name: "Bash"`, command
  `Set-Content …`); Chorus allowed it and the file was written. `dir` was denied with a message: the
  TUI showed "Blocked by hook" and the final message said the listing was skipped as requested.
- The relay must print a decision on stdout and nothing else. It was a Node script reading the token
  from its own environment; `cmd` would have expanded a `%TOKEN%` into curl's argv.
- **`codex queue`** from outside reached the embedded-mode TUI session: the rollout shows a second turn
  with `turn_trigger: "queue"`.
- Rollout records: `session_meta`, `turn_context`, `world_state`, `event_msg` (`task_started`,
  `task_complete` with `last_agent_message`, `item_completed` `UserMessage` / `AgentMessage`,
  `token_count`), `response_item`, `token_usage_record`. Plans and approvals are not persisted *(docs,
  confirmed by the record counts)*.

### opencode
- `opencode serve` on loopback with isolated `XDG_*` folders and basic auth from
  `OPENCODE_SERVER_PASSWORD` (environment only; 401 without it). The TUI ran **inside Chorus's PTY**
  as `opencode attach http://127.0.0.1:<port> --session <id>`, with the password injected from the
  vault.
- One `prompt_async` (204) produced, as SSE events: `session.status` busy, `todo.updated` (two todos),
  `question.asked` (with options), then after `POST /question/{id}/reply` `["hi"]`, `permission.asked`
  for the edit (with the full diff). `reply: "once"` wrote `hello.txt` containing "hi"; `permission.asked`
  for `dir` got `reply: "reject"` with a message, delivered verbatim to the model as the tool error.
  A second `prompt_async` sent mid-turn waited and ran after; `session.idle` fired once the queue
  drained. The attached TUI showed the question card, "Permission required" and the queued prompt, and
  cleared each when the API answered.
- The free provider stalled once (`ProviderHeaderTimeoutError` after 5 minutes); opencode retried and
  finished without a `session.error`.

### Grok
- Not signed in (`~/.grok/auth.json` absent; an expired August token was cleared on the S1 launch), so
  no turn could run. Everything in the Grok column comes from Grok 1.0.62's bundled docs, `--help`,
  `grok inspect` and the binary *(docs)*.
- Notable: hooks load only from global or project files (no `--settings`; `--plugin-dir` only in agent
  mode); an `http` hook URL expands `${VAR}`, and a hook whose variable is empty is skipped; a `PreToolUse`
  `allow` does not approve a prompt; this machine's `~/.grok/config.toml` sets
  `permission_mode = "always-approve"`, so Chorus must always pass `--permission-mode`; Grok reports
  `working`/`blocked`/`done` via OSC 7501 when the terminal answers its query.

## Findings outside the channels

1. **Grok updated itself on first launch.** S1 launched Grok before Chorus set any update switch; it
   replaced 1.0.5 with 1.0.62 (`grok.exe.old` kept). LESSONS L7 in action. Chorus now sets
   `GROK_DISABLE_AUTOUPDATER=1` (documented in 1.0.62) and should also pass `--no-auto-update`.
2. **Codex's Windows sandbox fails on this machine, inside or outside Chorus**: "Failed to create
   unified exec process: helper_unknown_error: setup refresh had errors". Not caused by Chorus, and
   not the shell: it failed the same way with Windows PowerShell 5.1 and a non-Store `pwsh`. The
   legacy `elevated` sandbox's setup helper fails to update the ACL on the desktop app's
   `node_repl.exe` because that file is running ("os error 32"). Turning on MXC fixes it
   (LESSONS L31).
3. **Claude Code's PowerShell permission parser fails on this machine, inside or outside Chorus**: every
   PowerShell command shows "Command contains malformed syntax that cannot be parsed: pwsh exited with
   code 1: The command line is too long." Not caused by Chorus. The `pwsh` found first on `PATH` is
   the Microsoft Store app alias; with a real `pwsh.exe` first the parser works (LESSONS L30).
4. **Minimal environment additions**: `PATHEXT` (Codex hooks) and `SystemDrive` (a Claude session left
   a literal `%SystemDrive%\ProgramData\…` folder in its working directory; a repeat without it did not
   recreate the folder, so the cause is inferred from the path).

## What it means for the plan

- **D29's condition is met for Claude Code**: Chorus can answer approvals (and questions) itself, and
  the agent's own dialog stays usable in parallel. Same for Codex approvals and all of opencode.
- **Token transport changes for the better** (D36): HTTP hooks with the token in a header from the
  child's environment, instead of Chorus 1's token-in-URL in a settings file.
- **Codex needs a relay executable** (D37): P3 adds a tiny `chorus-hook` binary to the workspace (reads
  the token from its environment, posts stdin, prints any decision), injected with `-c hooks.…` and
  `--dangerously-bypass-hook-trust`.
- **Turn tracking**: pair turns with `Stop` first-in-first-out (prompts can be queued before the
  previous `Stop`), and close a turn on interrupt by another signal (transcript, `Notification:
  idle_prompt`, PTY silence as the liveness backstop), since an interrupted Claude turn sends no `Stop`.
- **Plans**: Claude Code needs `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` (undocumented; treat as "try and
  report"); Codex has no plan channel in TUI mode, so Friendly says so (fail visible) unless P3 moves
  Codex to app-server + `--remote`; opencode works as designed.
- **Grok** stays PTY-only for P2 unless Matthew picks a structured route (OPEN-QUESTIONS Q18).
